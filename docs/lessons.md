# 我们踩过的坑：一套会遗忘的记忆系统，先得学会「别把自己撑爆」

> 这些不是理论，是这套方案在真实使用里留下的疤。按时间倒序。

## 一、`AGENTS.md` 超出注入预算，尾部被静默截断

**事实**（2026-10-27 实测）：

| 项 | 数值 |
|---|---|
| `AGENTS.md` | **66,170 字节**（357 行） |
| 注入预算 | **65,536 字节** |
| 超出 | **634 字节** |
| 实际注入 | 截断到 **65,244**，尾部约 **930 字节**被丢掉 |

**后果**：放在文件末尾的第 6~8 条规范，**每次会话都看不到**。规则写了，等于没写。
更糟的是它**不报错**——你不会收到「你的规则被截断了」的提示，只会在某天发现 agent 又犯了一个「明明写过」的错。

**修法**：

1. `AGENTS.md` 只放**判据 + 指针**，操作细节全部下沉到各工具 `README.md`；
2. 最该被执行的规则放**最前面**——越靠后 = 越可能根本不进上下文；
3. 改完量一下字节数，别靠感觉。

**结果**：66,170 → **27,142 字节（-59%）**，尾部不再截断，24 个指针目标先验证存在，14 条红线锚点复核无丢失。

## 二、触发条件写错：把「存档」绑在「会话结束」上

**原来的写法**：「每次会话结束必做」。
**问题**：长任务里这个条件**永不成立**——连着跑四五个小时、好几个回合，会话根本没「结束」，于是一次都没存。

**用户的质问**：「我发现你最近执行接近末尾的时候没有存档记忆的流程了，有做吗？」

**根因**：不是规则被删了，是**触发点选错了**。
**修法**：把触发器从「会话结束」改成「**每完成一个可独立成立的里程碑**」——
里程碑 = 探测/实验跑完一轮 · 一件交付落地 · 用户对某个判断点了头 · 一个待办被判成硬墙。

最小三动作：**会话日志 + 近期状态一行 + 项目档案或记忆索引一条**。
自检问题：**「这一轮产生的东西，隔一天还找得到吗？」**

## 三、信息密度和重要性倒挂

66 KB 的旧版里：

- **工具命令**占了约 60% 的版面；
- 最该被看见的「存档铁律」被埋在第五节，触发条件还写错了；
- 真正改变行为的判据只剩几行，混在大量「怎么跑命令」里。

**教训**：**「精简」的标准不是字少了，而是剩下的每一条都在能改变行为的位置上。**
判断准入的一句话：**「这条不在上下文里，我会不会违规 / 走错路 / 白忙一场？」**
会 → 留，压到一行；不会 → 下沉，换一行指针。

## 四、指针化时最容易出的两种错

1. **死链**：把细节搬到 README 后，指针写了个不存在的路径。→ 改完必须逐个 `Test-Path` 验证。
2. **搬丢红线**：精简时把「安全边界」当工具用法删了。→ 建立「红线锚点清单」，改完逐条 grep 复核。

本次实际抓到 1 处死链（`笔记入口点.md` 不存在，真实路径是 `笔记入口点/笔记入口点.md`），已修。

## 五、校验器不要断言「用户的选择」

给配置做自动校验时，原来的断言是「默认模型必须是 X」。
结果用户自己在 UI 里把默认模型改成了 Y，校验器报**假失败**。

**判据**：**断言「我没改它」，不断言「它应该是什么」。**
校验器的职责是证明「这次改动没有越界」，不是替用户做决定。

---

## 六、一条更早的教训：别用 RAG 解决「记住一个人」

试过把记忆切块、做向量检索。问题不是效果差，是**不可审**：
检索出来的片段没有日期、没有来源、没有「这条已被推翻」的标记，agent 会把三年前的旧结论当成今天的事实。

**结论**：分层文本 + 索引 + 置信度 > 向量库。
等到索引一页放不下，再考虑上检索。

## 附：现在这套链路的形状

```
会话开始
  ├─ AGENTS.md（<30 KB，判据 + 指针）
  ├─ 记忆索引（关键词 → 位置）
  ├─ 长期记忆（F1/F2，带日期与来源）
  └─ 近期状态（最近 2~4 周）

工作中
  └─ 每完成一个里程碑 → 三动作存档（日志 / 近期状态 / 档案或索引）

每周
  └─ 体检：过期标掉、重复合并、F0 清理、死链复查、矛盾留痕
```

它不保证 agent「说得对」，只保证它**记得你说过什么、并且知道自己是从哪知道的**。
